# 서브에이전트 프롬프트

서브에이전트는 이 대화를 보지 못한다. 아래 틀의 `<...>`를 실제 내용으로 채워 넘긴다. 줄임말과 인터뷰 중에 만든 별칭은 풀어 쓴다.

## 이해관계자 관점 검토

관점마다 에이전트 하나씩, 한 번에 병렬로 띄운다. 사용자가 확인해 준 명단만 쓴다.

```
어떤 계획을 한 사람의 입장에서 검토하는 일을 맡깁니다. 계획을 세운 쪽은 이 사람의
반응을 미리 알고 스펙에 반영하려 합니다. 듣기 좋은 평가가 아니라 이 사람이 실제로
제기할 만한 문제를 찾아 주세요.

당신이 맡을 입장:
- 역할: <역할. 예: 이 도구를 매일 쓰게 될 운영 담당자>
- 이 사람이 중요하게 여기는 것: <사용자가 말해 준 관심사>
- 이 일과의 관계: <결정권자 / 사용자 / 영향받는 쪽 / 승인자 등>

계획:
<목표, 배경, 현재까지의 결정과 범위를 그대로 붙인다>

이 사람의 입장에서 가장 문제 삼을 지점을 최대 3개까지 찾아 주세요. 문제가 3개보다
적으면 적게 내도 됩니다. 억지로 채우지 마세요. 각 항목에는 다음을 적어 주세요.
1. 계획의 어느 부분이 문제인지 (해당 결정이나 문장을 지목)
2. 왜 현재 계획으로는 이 문제가 해결되지 않는지
3. 그대로 진행하면 이 사람에게 어떤 일이 생기는지
4. 이 사람이 받아들일 만한 수정 방향 (있다면)

위 정보만으로 판단하기 어려워 추측한 부분은 추측이라고 표시해 주세요.
```

받은 뒤에는 SKILL.md의 세 가지 근거(어디가 비었는지, 왜 안 정해졌는지, 방치 시 결과)를 기준으로 걸러서, 통과한 것만 사용자에게 가져간다. 여러 관점이 같은 지점을 지목했으면 하나로 합치고 누가 지목했는지 적는다.

## 독립 감사

스펙 파일 경로만 준다. 대화 내용이나 내 판단을 덧붙이지 않는다. 덧붙이면 감사자가 스펙의 빈틈을 내 설명으로 메워 읽게 된다.

```
<스펙 파일 절대 경로>에 있는 스펙을 읽어 주세요. 이 스펙은 사용자와의 인터뷰로
만들어졌고, 인터뷰를 보지 못한 AI 에이전트가 이 파일만 받아 작업을 실행하게 됩니다.
당신도 인터뷰를 보지 못했으니 그 에이전트와 같은 조건입니다. 실행 전에 스펙의
빈틈을 찾는 것이 목적입니다. 파일은 수정하지 말고 보고만 해 주세요.

이 파일만 가지고 작업을 시작한다고 생각하고 다음을 찾아 주세요.
- 막히는 질문: 답이 없으면 작업을 시작하거나 끝낼 수 없는 것
- 검증할 수 없는 성공 기준: 달성 여부를 판정할 방법이 불분명한 것
- 서로 모순되는 문장
- 뜻을 알 수 없는 용어나 설명 없이 쓰인 고유명사
- 범위가 불분명해 사람마다 다르게 해석할 부분

각 항목에 스펙의 해당 위치와, 그것이 왜 실행을 막거나 결과를 바꾸는지를 적어 주세요.
실행에 영향이 없는 문체나 형식 지적은 필요 없습니다. 문제가 없으면 없다고 답해 주세요.
심각한 것부터 나열해 주세요.
```
